# 15 隐私与访问矩阵

## 1. 目标

本文件记录随缘网当前真实的数据可见边界。新增页面、接口或运营能力不得仅依赖前端隐藏；敏感数据的最终边界必须由服务端规则保证。

## 2. 当前角色

- **游客**：未登录访问者。
- **会员**：已登录普通会员。
- **关系双方**：涉及本人关系记录的会员，例如心动双方、聊天双方。
- **活动主办方**：本人创建活动的发起人。
- **掌柜**：管理员，仅为运营处置使用，不代表可以无目的浏览全部敏感资料。

## 3. 第一批最少披露矩阵

| --- | --- | --- | --- | --- | --- |

## 4. 游客数据原则

游客首页只使用本地明确标注的演示人物、演示帖子和演示活动。客户端未登录水合不得请求真实 `profiles / posts / events / digests / content_likes / event_attendees` 等业务集合；服务端对应集合也要求登录后读取。

真实成功故事只有在获得展示授权且来源可核实时才进入公开站点设置；否则必须标记为示例。

## 5. 会员资料原则

- 未填写的个人事实保持未知，不由系统代填。
- 城市用于推荐；更细地区仅在用户主动填写时存在，不应作为实时位置解释。
- 核验状态只表达对应核验流程的记录，不等于单身、财产、品行或线下见面安全保证。
- 联系方式不进入公开会员资料；活动报名联系方式仅本人、对应活动主办方及必要运营处置可见。

## 6. 消息与关系原则

- `user_likes` 只代表会员本人真实操作。
- 非 mutual 不能创建聊天消息，前后端均执行该约束。
- 消息发送者、会话双方、关系归属字段不可通过更新接口改写。
- 输入中、已读、回复等状态只能来自真实业务事件，不允许模拟成另一位会员的行为。
- 活动签到记录只能经现场核销端点创建；服务端校验报名关系、签到时间窗与 6 位核销码。
- 举报处理结果写回举报工单本身，不通过私聊冒充平台/管理员通知。

## 7. 真实试点遥测原则

- 人物推荐曝光只由服务端在候选真正返回给用户后记录，客户端不能自行上报或伪造曝光。
- 原始字段最小化为 viewer / target / source / day / at；不记录点击轨迹、停留时长、私信正文、页面滚动或连续行为序列。
- 同一 viewer-target-source 在同一上海日期只保留一条，刷新/重试不会放大计数；在线原始表按 35 天窗口治理。
- `discovery_exposures` 无通用 collection 权限；普通会员不能读，管理员也不能直接枚举原始明细。掌柜只能经专用端点读取聚合供给、曝光公平与漏斗指标。
- 试点聚合排除演示账号、管理员与停用账号；账号永久注销时同步删除其作为 viewer 或 target 的曝光行。

## 8. 图片与附件原则

- 新上传图片必须声明用途：`profile / post / event / chat / admin`。
- 新文件使用不可猜文件名 + HMAC capability URL；缺少或篡改签名时服务端返回 404。
- 服务端校验声明 MIME 与图片 magic bytes 一致，拒绝伪装格式；响应增加 `nosniff`，缓存改为 `private`。
- 上传失败时前端不再把 dataURL 静默写入业务表，只有真实落盘成功后才返回可保存 URL。
- 2026-09-28 已对真实 `public` 扫描全部 9 个图片字段，未发现 legacy URL 引用；因此未执行写迁移，legacy unsigned HTTP 读取已直接关闭。磁盘残留 legacy 文件即使真实存在也统一 404。
- capability URL 本质仍是持有即访问的凭证，不应把它当成“实名授权”；聊天图片、个人照片等如需更强粒度，应进一步升级为短期签名或登录态媒体代理。

## 9. 仍需继续收紧的项目

1. legacy unsigned 图片边界已闭环；后续仅评估聊天图片、个人照片是否需要从长期 capability 进一步升级为短时签名或登录态媒体代理。
2. 补充账号恢复自助路径；公开安全与隐私说明、资料导出和永久注销入口已落地。
3. 继续扩充角色级回归测试；当前 13 条真实 Neon 隔离 E2E 已覆盖注册/登录、发现、互动、活动、私信、举报、上传 capability、账号生命周期和内容安全主链路。
4. 定期复核管理员读取权限，避免“能处理投诉”演变成无目的全量浏览。
