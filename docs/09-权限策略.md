# 09 权限策略

## 角色

| 角色 | 判定 | 能力边界 |
| --- | --- | --- |
| 访客 | 未登录 | 官网首页、登录注册页；其余路由跳转登录 |
| 会员 | 登录账号（role 为空） | 功能开关开启的各模块；只能写自己的私有数据 |
| 掌柜 | 登录账号 role = admin | 会员全部能力 + 后台五个页签（含处置与数据维护） |

页面准入矩阵见 `03-页面清单.md`；功能开关（yuanfen / explore / events / community / matches）由掌柜在站点设置中调整，关闭时会员端显示统一提示页。

## 服务端规则现状（2026-09-08 盘点并加固后）

| 表 | 读 | 写（create / update / delete） |
| --- | --- | --- |
| users | 仅本人 | 注册开放；改 / 删仅本人 |
| profiles | 全员可读（公开目录） | 建：登录；改：本人或掌柜；删：掌柜 |
| posts / post_comments / events / event_comments / digests | 全员可读 | 建 / 改：登录成员；删：掌柜（**残留风险见下**） |
| chat_messages | 登录成员可读 | 仅会话双方或掌柜 |
| user_likes | 双方或掌柜 | 仅 owner（删含掌柜） |
| user_passes / blocks | 双方或掌柜 | 仅 owner（删含掌柜） |
| user_reads / favorites / fav_groups / reminders / user_tour | 仅 owner 或掌柜 | 仅 owner（删含掌柜） |
| visits | 走访双方或掌柜 | 仅 viewer（删含掌柜） |
| contacts | 登录成员可读（活动主办需读报名者名片） | 建 / 改仅本人；删本人或掌柜 |
| checkins | 登录成员可读（主办需跨行核签到） | 登录成员 |
| reports | 举报人或掌柜 | 建：仅本人；删：掌柜 |
| admin_logs | 仅掌柜 | 写：仅掌柜 |
| site_settings | 全员可读（功能开关需会员端可见） | 仅掌柜；不可删 |

## 本轮加固记录（2026-09-08）

- 12 张表收紧：profiles 改、contacts 建、reports 建、admin_logs 写，以及 favorites / fav_groups / user_passes / user_reads / blocks / reminders / user_tour / visits 的读与改删，全部落到「本人（或关系双方）+ 掌柜」语义。
- contacts 的读保留「登录成员」：活动主办要在活动详情读报名者交换的名片，规则表达不了跨表关系，回滚并在下方登记为残留风险。

## 残留风险与计划

1. **公共内容表 update 对成员开放**：点赞名单、报名名单、浏览量都需要成员跨行更新，代价是理论上可改他人正文 / 精选位。计划：服务端钩子做字段级校验，或把点赞 / 报名 / 浏览拆独立表（走 08 迁移流程）。
2. **checkins / contacts 读对成员开放**：主办视角的跨行读取无法用单表规则表达。计划：同上，钩子校验「同活动且已报名 / 主办」。
3. **无公网限流**：当前为容器内网部署，边界 = 内网 + 服务端规则 + 运营日志审计。若接公网，先补限流再开放。

## 审计

- 后台处置动作写运营日志，日志仅掌柜可读可写。
- 数据盘点与备份导出仅后台入口提供；备份文件剥离会话签名密钥字段。
