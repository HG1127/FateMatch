# 09 权限策略

## 角色

| 角色 | 判定 | 能力边界 |
| --- | --- | --- |
| 访客 | 未登录 | 官网首页、登录注册页；其余路由跳转登录 |
| 会员 | 登录账号（role 为空） | 功能开关开启的各模块；只能写自己的私有数据 |
| 掌柜 | 登录账号 role = admin | 会员全部能力 + 后台五个页签（含处置与数据维护） |

页面准入矩阵见 `03-页面清单.md`；功能开关（yuanfen / explore / events / community / matches）由掌柜在站点设置中调整，关闭时会员端显示统一提示页。

## 服务端规则现状（2026-09-23 计数拆分后）

| 表 | 读 | 写（create / update / delete） |
| --- | --- | --- |
| users | 仅本人 | 注册开放；改 / 删仅本人。**停用（profiles.banned）账号登录与持令牌请求一律 403**（v1.6 服务端强制，此前只在客户端过滤） |
| profiles | 全员可读（公开目录） | 建：登录；改：本人或掌柜；删：掌柜。**role / banned 字段仅掌柜可写**（防自我提权 / 自我解封，网关字段级拦截） |
| posts | 全员可读 | 建：登录成员；改：作者本人或掌柜；删：掌柜 |
| post_comments | 全员可读 | 建：登录成员；改 / 删：作者本人或掌柜 |
| events | 全员可读 | 建：登录成员；改 / 删：发起人本人或掌柜 |
| event_comments | 全员可读 | 建：登录成员；改 / 删：作者本人、掌柜、或所属活动发起人（发起人用于置顶 / 清理自己活动下的留言，网关跨表判定） |
| digests | 全员可读 | 建 / 改 / 删：仅掌柜。浏览计数走原子自增端点（登录成员触发，客户端不再整行覆写） |
| content_likes（点赞名单） | 全员可读 | 建 / 删：仅本人行（删含掌柜）；不可改 |
| event_attendees（报名名单） | 全员可读 | 建 / 删：仅本人行（删含掌柜）；不可改。**建时服务端满员校验**（v1.2：锁活动行同事务计数，超员拒绝） |
| chat_messages | 会话双方或掌柜（v1.6 收紧，此前任意登录成员可读全站私信） | 仅会话双方或掌柜；**任一方拉黑对方后建行被拒**（v1.6 服务端强制拉黑语义） |
| user_likes | 双方或掌柜 | 仅 owner（删含掌柜）；**拉黑双方之间心动建行被拒**（v1.6） |
| user_passes / blocks | 双方或掌柜 | 仅 owner 本人行（v1.6 收紧建 / 改，此前任意成员可写他人行；删含掌柜） |
| user_reads / favorites / fav_groups / reminders / user_tour | 仅 owner 或掌柜 | 仅 owner 本人行（v1.6 收紧建 / 改；删含掌柜） |
| visits | 走访双方或掌柜 | 仅 viewer（删含掌柜） |
| contacts | 本人行 + 自己发起的活动下的行 + 掌柜（v1.2 收紧：名片含联系方式，不再全员可读） | 建 / 改仅本人；删本人或掌柜 |
| checkins | 本人行 + 自己发起的活动下的行 + 掌柜（v1.2 收紧） | 仅本人行；删含掌柜 |
| reports | 举报人或掌柜 | 建：仅本人；删：掌柜 |
| admin_logs | 仅掌柜 | 写：仅掌柜 |
| site_settings | 全员可读（功能开关需会员端可见） | 仅掌柜；不可删 |

## 残留风险与计划

1. ~~**公共内容表 update 对成员开放**~~ **已解决（2026-09-23 计数拆分）**：点赞 / 报名名单拆到 content_likes / event_attendees 独立表（仅本人行可写），浏览计数改网关原子自增端点；posts / post_comments / events / event_comments 的 update 收紧到「作者 / 发起人 + 掌柜」，digests 收紧到「仅掌柜」。主表旧名单列保留但网关已屏蔽读写（回退兜底）。迁移：40 条点赞 + 16 条报名逐条核对一致。顺带修复两处界面与服务端不一致：评论作者删自己的评论、活动发起人删自己活动（此前服务端只认掌柜，非掌柜的删除会被静默拒绝、刷新后复现）。同时补上 profiles.role / banned 的字段级防护（此前成员理论上可通过改自己的资料行自我提权）。
2. ~~**checkins / contacts 读对成员开放**~~ **已解决（2026-09-23 v1.2）**：列表范围收紧为「本人行 + 自己发起的活动下的行 + 掌柜」（HOSTED 范围，子查询判定发起人）；单行读同语义（跨表函数规则）。名片联系方式不再对无关成员暴露，与界面「仅发起人可见」的展示语义对齐。写侧同步收紧：checkins 建 / 改仅本人行（此前任意成员可写他人签到行）。
3. **无公网限流** **部分解决（2026-09-23 v1.4）**：网关内置内存固定窗口限流——全局单 IP 1200 次/分、登录接口单 IP 60 次/10 分、注册单 IP 20 次/时，超限返回 429；登录防爆破：同一邮箱连续错 8 次密码锁 15 分钟（锁定期正确密码也拒，按邮箱隔离不误伤他人）。单进程内存语义、重启清零，适配当前容器单实例部署；若接公网或多实例，需升级为网关/WAF 层限流与共享计数（如 Upstash）。
4. ~~**活动满员校验在客户端**~~ **已解决（2026-09-23 v1.2）**：报名建行时网关在同一事务内对活动行加锁（for update）后计数校验，超员返回字段级 400「活动已满员」；并发抢最后一个名额不会超员。本人已有报名行时幂等返回不算新增；退订后名额即时释放。已知边界：被服务端拒绝的报名在前端为静默失败（本地态到下次刷新才纠正），界面按钮本身有满员禁用，仅并发竞态时可见。
5. **公开表 create 的归属冒充**：posts / events / profiles 的建行为「任意登录成员」，author_sid / creator_sid / sid 可填他人 id（改 / 删已有规则保护，冒充仅影响新建内容的署名展示）。暂不收紧的原因：种子同步架构依赖任意用户把演示内容行（author_sid = 种子用户）同步入库，收紧会让全新安装环境的种子内容及其评论 / 点赞失去共享载体。整改计划：改为服务端种子化（一次性脚本灌入演示数据）后，把三表 create 收紧到「本人字段 + 掌柜」。

## 审计

- 后台处置动作写运营日志，日志仅掌柜可读可写。
- 数据盘点与备份导出仅后台入口提供；备份文件剥离会话签名密钥字段。
- 输入尺寸护栏（v1.3）：全部业务写路径经字段级校验（文本字符数 / 数组元素数上限，超限返回字段级 400），界面 maxLength 与之配套；防异常客户端写入超大内容拖垮全量同步。请求体字节数另有 25MB 上限兜底。
