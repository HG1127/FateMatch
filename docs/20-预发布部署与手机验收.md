# 随缘网｜预发布部署与真实手机验收手册 V1.0

核查日期：2026-10-09
阶段：**预发布设施准备及隔离环境测试**。此仓库尚未绑定可公开访问的 staging 服务器、域名和独立数据库；不能视为已经完成远程预发布部署。

## 1. 环境分层（强制）

| 环境 | 数据库与附件 | 可访问性 | 用途 |
| --- | --- | --- | --- |
| E2E 一次性环境 | `e2e_smoke_*` Neon 临时 schema + 临时附件，结束清除 | 仅回环 127.0.0.1:7200 | 自动化合约/浏览器测试，绝不邀请真实用户 |
| Staging 预发布 | **独立数据库账户与库** + `staging_*` schema + 独立图片卷 | 独立 staging HTTPS 域名，访问受限 | 内测、真实设备验收、小规模用户试点 |
| Production | 正式独立数据库 `public` + 正式附件卷 | 正式域名 | 仅在另行审批及备份后开放 |

禁止用正式 `NEON_DSN` 直接替代 `STAGING_NEON_DSN`，也禁止将预发布 schema 设置为 `public`。模板 `compose.staging.yml` 只暴露宿主回环 `127.0.0.1:8081`，必须由部署主机的认证 HTTPS 反向代理提供受限域名。对外 HTTPS 必须有有效证书。Staging 特有环境变量 `STAGING_MODE=1` 在网关启动时检查 schema 前缀，并对响应加 `X-Robots-Tag: noindex` 与 `Cache-Control: no-store`；**这些响应头不是访问认证**，仍须代理加准入限制。

## 2. 已准备的工程交付

- `compose.staging.yml`：与生产同 Dockerfile；隔离 Compose 项目、图片卷、环境变量与本地端口，非 root、只读根、能力清空
- `deploy/nginx-staging.conf.example`：HTTPS + Basic Auth 受限访问的 Nginx 模板；配置时替换实际 staging 域名、证书和不入库的用户名密码文件。反向代理必须覆盖 `X-Forwarded-For`，不信任客户端自带值。
- `scripts/staging-preflight.mjs`：只读校验独立 staging 凭据、schema/端口以及环境中可见的生产连接是否相同；不回显 DSN
- `scripts/staging-migrate.mjs`：默认 dry-run；只有显式 `--apply --confirm=<准确的 staging schema>` 才会执行幂等迁移
- `scripts/staging-smoke.mjs`：无账号、无数据写入地验证 HTTPS/本地入口、页面、`/api/health`、`/api/ready`、禁止静态暴露 `.env`、noindex 响应头
- `e2e/mobile-acceptance.spec.ts`：真实 Chromium + 触摸屏模拟的 320 / 375 / 390 / 768 px 关键旅程与横向溢出检查，截图在被 Git 忽略的测试目录
- GitHub CI：验证 `compose.staging.yml` 静态配置，但**不接触任何 staging 密钥或真实数据库**

## 3. 目标服务器上执行（需先取得独立数据库和域名）

1. 在独立预发布数据库上建立只读/写权限合适的专用账号，在受控密钥管理中配置 `STAGING_NEON_DSN`；另设 `STAGING_SCHEMA=staging_rc1`、`STAGING_PORT=8081`。不要存入仓库、前端或聊天，也不要在控制台显示连接串。
2. 检查准确部署版本及清洁工作区（`git rev-parse HEAD`、`git status --porcelain`），将该提交记录进验收单。
3. 运行 `pnpm staging:check`（只读），预先为 staging **数据库和附件卷**建立备份或确认全新空库，运行 `pnpm staging:migrate`（只读 SQL dry-run）。
4. 经部署负责人确认隔离数据库后，运行 `pnpm staging:migrate --apply --confirm=staging_rc1`；不得执行针对 `public` 的迁移。
5. 在目标 Docker 主机运行：
   ```bash
   docker compose -f compose.staging.yml config --quiet
   docker compose -f compose.staging.yml build
   docker compose -f compose.staging.yml up -d
   docker compose -f compose.staging.yml ps
   ```
6. 仅本机内部先执行 `pnpm staging:smoke`，检查日志不包含 DSN 或用户内容。随后由独立受限 HTTPS 反向代理接入 staging 域名，再执行 `pnpm staging:smoke --url=https://staging.example.org`（按实际域名替换）。若代理需要身份认证，先在允许的受控环境完成相关检查，勿取消认证来方便脚本运行。
7. 核查图片新建/签名读取、接口权限拒绝、刷新深链、取消报名、举报工单及持久化。测试只用获授权的内测账号；`X-Robots-Tag` 与 robots.txt 不替代 Basic Auth/VPN/IP allowlist。
8. 保存阶段产物：Git SHA、Docker 镜像 digest、迁移审计、独立图片卷、健康探针截图、证书/域名检查、回退点与试点权限列表；验收通过后才开放真人邀请。

**回退原则**：先恢复上一镜像/代码版本，保留已做的向后兼容新增列；不要用 `DROP SCHEMA`、覆盖 `public` 或重灌测试数据作为回退方案。当前单机网关的内存限流不适合未经设计直接多实例扩容。

## 4. 真实手机验收矩阵

自动化测试只能证明**浏览器模拟设备行为**，并非接入实体 iPhone/Android。正式开放测试用户前，至少需两位独立测试者在真实设备通过以下检查并记录设备型号、系统、浏览器版本与时间：

| 场景 | iOS Safari（真机） | Android Chrome（真机） | 判定 |
| --- | --- | --- | --- |
| 注册、登录、刷新及退出 | 待人工验收 | 待人工验收 | 无循环登录、无错误状态 |
| 四个底部导航、弹窗关闭、浏览器后退 | 待人工验收 | 待人工验收 | 可见可点，不被安全区域遮挡 |
| 320/375/390/430 宽的横向溢出与横屏 | 适用机型检查 | 适用机型检查 | 页面不需要意外横向滚动 |
| 资料保存、照片选择及设头像 | 待人工验收 | 待人工验收 | 真正保存、失败不丢编辑 |
| 双向有意、消息输入、草稿与提醒 | 待人工验收 | 待人工验收 | 不制造假 mutual/假已读 |
| 活动时间地点与费用、报名取消 | 待人工验收 | 待人工验收 | 费用说明正确、撤销可见 |
| 举报/拉黑、隐私、账号注销 | 待人工验收 | 待人工验收 | 无越权、无非预期数据外泄 |
| 较慢移动网络、断网恢复与弱电 | 待人工验收 | 待人工验收 | 明确提示，可重试 |
| 键盘弹起、滚动到底、页面缩放 | 待人工验收 | 待人工验收 | 输入框及“发送”可操作 |

需用真实 HTTPS staging 域名让手机访问，严禁将正式数据泄露给自动化测试；真机报告只放受限工单/运营库，不在公开 Git 上传截图中的个人信息。
