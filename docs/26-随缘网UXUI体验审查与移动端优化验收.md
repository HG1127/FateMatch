# 随缘网｜用户体验审查与移动端优化验收（2026-10-10）

> 范围：独立站 React 前端。基于真实代码/组件与浏览器模拟验证，而非真人可用性访谈。未访问或修改生产会员数据；未发布至线上。保留原有中国风品牌配色与桌面业务流程。

## 一、从用户操作任务出发的 UX 问题

| 用户任务 | 审查发现的交互负担 | 本次改进 | 验收重点 |
| --- | --- | --- | --- |
| 填写真实生日 | 原生日期选择器跨几十年不直观，各移动浏览器行为不同 | 四位年份直接输入＋原生月份、日选择；十八岁边界、闰年及月份长度校验 | 无需逐月翻页；非法日期不写入资料 |
| 从活动日历找指定时间 | 原日历只能一月一月翻 | 年、月独立快速跳转；回本月、明确日期/活动状态 | 快速跳转/反复切换月份不出现上月旧数据 |
| 手机上进入兴趣筛选/同城/社区 | 之前底部仅推荐、活动、消息、我的；低频功能要到顶部菜单 | 五个底部触达目标，增加“发现”按钮直达全部次级功能 | 操作面积、关闭焦点回到触发按钮、底部安全区 |
| 手机上发起活动 | 日期难跳、长表单拥挤、相册排序只适合拖动 | 今天/明天/本周六快捷日期、分段日期选择、相册手机箭头排序、扩大图片操作按钮、关闭按钮避让 | 点击、日期正确性、保存流程保持不变 |
| 手机上查找他人 | 桌面式横排的省市区选择器易挤占屏宽，年龄输入分散 | 手机两列地区选择＋通栏区县，两列年龄范围、较大定位按钮和可读的分组 | 320px 无横向溢出，清空筛选真正恢复选择器状态 |
| 我的照片与隐私 | 手机上三列缩略图及小图标易误触、排序欠直观 | 双列照片，更大设头像/删除/顺序按钮；隐私开关扩大触控范围 | 触控操作不会意外覆盖其他照片 |
| 手机首页第一操作 | 长标题与并排 CTA 抢空间；统计卡过长 | 标题字号响应式收敛、主要 CTA 改为手机通栏；两列任务概览 | 320–430px 下无拥挤与意外横向滚动 |

## 二、统一移动体验原则

1. **高频任务单手可达**：底部推荐、发现、活动、消息、我的；详细功能仍保留原路径。
2. **减少任务操作次数**：日期直接输入年份、年月定位和快速时间按钮，不再靠重复滑动。
3. **触控优先，非缩小版桌面**：主要控件遵循约 44px 可点击目标；图片排序提供触屏操作路径。
4. **减低视觉噪声**：手机采用系统可读中文正文字体，减少多重装饰边框；品牌书法标题与红金色仍保留。
5. **重要状态可信**：异步切月忽略陈旧响应，资料与活动继续由真实服务端写入确认，失败不谎报成功。
6. **尊重私密数据**：测试仅用隔离合成接口，不用真实用户照片/聊天/生产数据库执行检查。

## 三、自动化证据与发布边界

- 静态检查：`pnpm lint`
- 单元测试：`pnpm test`（包括新的分段日期、闰年、边界、资料回填回归）
- 生产构建：`pnpm build`
- 模拟手机端到端走查：`pnpm mobile:check`，覆盖 320×568 / 375×812 / 390×844 / 430×932 / 768×1024，以及受限网络提示、导航、消息、资料、活动日历、活动发布表单和探索筛选。该检查使用本地页面和全量合成 API mock，不连接 Neon 正式数据库。

## 四、正式发布前仍需验证的项目

- **真实手机**：iPhone Safari 和 Android Chrome 上核验年月控件原生菜单、软键盘、返回手势、安全区、照片权限和触摸精度；模拟 Chromium 不能完全替代实机。
- **可用性测试**：让首次使用者独立完成注册、填写生日、进入推荐、发现同城、发起活动、聊天等场景，记录完成率、误触、返工、耗时与主观难度。当前没有真实用户样本，不能宣称提升了具体转化率。
- **设计系统**：后续逐步统一页面空白/错误/加载反馈、表单字段校验、图片管理、无障碍对比度与屏幕阅读器顺序。此轮未完成全站所有管理端页面的逐像素审查。
- **上线授权**：修改仅保留在当前独立项目工作区；不要未经授权部署、推送或迁移数据库。上线后还需完成服务端和隐私安全回归。
