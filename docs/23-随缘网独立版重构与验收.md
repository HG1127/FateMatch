# 随缘网独立版｜VibeX 解耦与验收（2026-10-10）

## 结论与变更边界

- 工作分支：`refactor/standalone-suiyuan`，由已验证的 `staging/vercel-split` 分支分出。**不要直接覆盖 main、当前 Vercel/Render、现有 Neon Staging 或正式 public 数据库**。
- React + Vite、Node Gateway、Neon PostgreSQL 是实际运行链路。业务逻辑（资料、互配、聊天、活动、社区、风控、管理员、注销）保留。
- 独立版 `pnpm dev:full` 增加专用账号/库名/schema 防误连检查；已有 7000 端口网关将不再自动复用，防止本机误把开发访问指向生产库。
- 移除前端 VibeX/RunningHub 可视化编译插件、项目子路径侦测和专用令牌头，页面始终使用同源根路径 `/` 和 `/api/*`。
- 保留 PocketBase **JavaScript SDK** 作为客户端 HTTP 请求和会话管理工具，**不需要运行 PocketBase 服务端**。完全去掉 SDK 需后续单独实现并审计 token 刷新、分页、错误映射和并发安全，当前不冒险替换。
- Node 网关仍接受 `/__pb/api/*` 与 `X-Pb-Auth` 作为回滚别名；新客户端不会再主动使用它们。等真实灰度日志确认旧客户端为零时，再单独制定废弃版本与日期。

## 具体已处理

| 层面 | 新行为 | 兼容/留存 |
| --- | --- | --- |
| `vite.config.ts` | 删除 `rhSourcePlugin`、`data-rh-src`、`errLogPlugin`，只保留 React/Vite；开发服务器默认绑定 127.0.0.1 | `LOCAL_FULLSTACK=1` 的本机代理仍支持 `/api` 和旧 `/__pb` |
| `src/lib/pb.ts` | API base 改为 `window.location.origin`，所有集合请求发往 `/api/collections` | 沿用独立版的 `pb_auth_local` 会话存储键 |
| `src/lib/localAuth.ts` | 裸 fetch 统一 `Authorization`，登录跳转为 `/auth` | 已有登录/注销逻辑与权限约束不变 |
| `src/App.tsx` | React Router 无特殊 basename | 深链接必须由站点配置回退 `/index.html` |
| `src/lib/upload.ts` | 只接受 `/api/uploads/` 签名地址并补全本站 origin | 真正图片上传依赖持久化文件存储，Render Free 禁止真人上传 |
| `index.html` | favicon 指向 `/favicon.svg`，移除 Google Fonts CDN 访问 | 使用系统宋体、楷体后备字形；不同设备字体外观会有细微变化 |
| `src/lib/utils.ts` | 异常仅在浏览器控制台可见，不再通过 GET /__err 泄露 URL 堆栈 | 生产排障需要另行接入合规的日志与敏感信息过滤 |
| `.rh/*` | 独立分支不跟踪 RH 模板元数据 | 原 Git 分支历史和本地未跟踪的 VibeX 导出工具均保持原样 |
| 历史迁移 | 旧 PocketBase 数据镜像脚本归档到 `scripts/legacy/`，独立版禁用写入 | 只允许 `--dry`；如需真正恢复迁移，必须从旧分支提取并单独审批、备份 |

## 验收命令（无需触碰正式数据库）

```bash
pnpm install --frozen-lockfile
pnpm lint
pnpm test
pnpm build
pnpm standalone:check
# 以下仅在已配置一次性 Neon 测试连接、并确认 7200 端口空闲时运行
pnpm e2e
```

`standalone:check` 为只读检查；验证前端源码没有 VibeX 插件/字体跨境外链、静态资源路径、旧迁移禁写、服务端的回滚别名；不会访问云 API 或数据库。

E2E 必须创建并销毁 `e2e_smoke_*` schema，后端的正式数据库 `public` 不得用作测试目标。不能把浏览器模拟触屏结果当作实际 iPhone/Android 手机验收。

## 部署与回滚

1. 只在新分支验证和提交。当前 `staging/vercel-split` 仍代表已经部署的 Render/Neon Staging 版本，不会随本分支代码变更。
2. 预发布若要升级，另行选择一个新测试项目，或在审计和批准后变更现有测试平台 Git 分支/显式部署 SHA，并确认 `STAGING_MODE=1`、`NEON_SCHEMA=staging_*`、媒体禁写或有持久化存储。先备份并确认日志、授权、图片、账号注销。
3. 如果客户端升级异常：把后端与前端均回滚到已验证的 `8578fbb`（或发布清单标记的上个可用 SHA）。迁移期保留 `/__pb` 和 `X-Pb-Auth`，确保旧客户端可回退。
4. 只有验收注册、登录、资料、双向有意、聊天、举报、删除账号、签名图片及实际移动端兼容后，才考虑批准并合并到 `main`。

## 明确未解决问题

- **中国大陆免 VPN 公网可达性没有因 VibeX 代码剥离而解决**。Vercel、Render 与 Neon 仍是跨境基础设施。需要另选可实测连通的国内入口/服务器或国内可用隧道，外加合规和适当的访问门槛。
- 当前免费 Render 实例的文件存储不持久；即使技术测试通过，也**不能向真人承诺照片已安全保存**。
- 系统没有自动完成大陆域名备案或个人信息保护合规审核。不能将本次独立化代码提交等同于正式发布许可证。
