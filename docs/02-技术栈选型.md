# 02 技术栈选型

流程推荐标准 vs 本项目实际选型。原则：**已在运行且承载真实数据的选型不推翻**；推荐标准中未被采用的项，给出理由与未来的切换点。

| 环节 | 推荐标准 | 本项目选型 | 理由 / 切换点 |
| --- | --- | --- | --- |
| AI Coding | Claude Code + Codex | Claude Code | 一致 |
| 仓库 | GitHub | 本地 Git（远端待配置） | 容器环境无远端凭据；接入远端后升级 |
| 包管理 | pnpm | pnpm | 一致 |
| 语言 | TypeScript (strict) | TypeScript strict | 一致 |
| 全栈框架 | Next.js (App Router) | Vite + React 19 + React Router 7 | 纯前端 SPA + 独立数据服务的部署形态，不需要 SSR；重写为 Next 收益低、风险高 |
| UI / CSS / 组件 | React / Tailwind / shadcn-ui | 一致（Radix + Tailwind + 组件清单见 04） | 一致 |
| 校验 | Zod | Zod | 一致 |
| 数据库 | Neon PostgreSQL | PocketBase（SQLite 存储） | 环境已启用、自带管理台与服务端权限规则；已承载真实数据 |
| ORM | Drizzle | 数据服务 SDK + 自建仓储层 | 仓储层承担 Schema 映射、差量同步、删除护栏；若未来换 Drizzle，仓储层是唯一替换点 |
| 认证 | Auth.js | 自建账号（邮箱 + 密码，存于账号表） | 容器部署无外部身份源；会话令牌经代理头透传 |
| 单元 / 组件测试 | Vitest / RTL | Vitest（本轮接入）；RTL 视需要补 | — |
| E2E | Playwright | 待评估（容器内无浏览器依赖时以冒烟脚本替代） | 见测试体系决策 |
| 部署 | Vercel Preview & Production | 容器内 8000 端口对外服务（硬性约束） | 预览环境可用云部署替代，待用户配置 |
| CI/CD | GitHub Actions + Vercel | 本地三道闸：lint + 构建 + 单元测试 | 接远端后补 Actions |

## 能力边界

- 数据服务监听容器内 7000 端口，前端经代理路径访问；对外唯一入口是 8000。
- 无公网速率限制设施：安全边界依赖「容器内网部署 + 服务端权限规则 + 后台审计日志」，见 09。
- 文件上传走数据服务自带存储。

## 决策记录

- 2026-09-08：确认不迁移 Neon/Drizzle/Next.js。迁移将破坏在线真实数据且无产品收益；流程的工程设计步骤（领域模型 / 契约 / Schema / 迁移策略）在现有栈上同等落地。
