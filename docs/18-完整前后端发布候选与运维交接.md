# 随缘网｜完整前后端发布候选与运维交接 V1.0

核查日期：2026-10-08。状态：**代码级发布候选（Release Candidate），尚非已上线生产版本**。

## 一、架构与职责

- 前端：React + TypeScript + Vite、React Router 按需加载、移动底部四导航、真实数据可信闸门、错误恢复。
- 后端：Node.js HTTP Neon Gateway、auth/profiles/matching/messaging/events/safety/admin 七个领域模块、服务端鉴权与数据权限、HMAC 签名媒体。
- 数据：Neon PostgreSQL，真实 `public` 为生产数据，测试严格使用一次性 `e2e_smoke_*` schema，结束销毁。
- 正式同源部署：`pnpm build` 产出 `dist/`，`pnpm start:prod` 在同一端口提供前端静态资源、深链刷新、`/api/*`、`/__pb/api/*` 与签名图片。
- 容器：`Dockerfile` + `compose.prod.yml` + `.dockerignore`，单实例、非 root、只读根、进程限制、持久化附件卷和本地绑定端口，由可信 HTTPS 反向代理对外提供服务。
- VibeX Source 另有专用平台回传流程；**仅上传 VibeX 前端不等于部署 Node 后端**。

## 二、本轮实际修改

1. 移除 Playwright 对多余 Vite 7300 页面服务的依赖，测试统一访问 7200 正式构建同源网关，避免开发服务器残留造成假失败。
2. 新增并测试 `server/client-ip.mjs`：默认不信任客户端自填 `X-Forwarded-For`，仅显式 `TRUSTED_PROXY_IPS` 内的直接代理可提供单一合法 IP，守住限流和审计地址。
3. 解决聊天首次成功发信后反馈入口需要重新进入会话的问题；状态即时刷新，不扩大登录首包。
4. 修复账号注销与已读状态更新竞争：`UPDATE ... RETURNING *` 原子返回；更新目标已消失时返回明确 404，不再对未定义记录访问。
5. 补入真实浏览器“双方有意 → 网页发信 → 反馈保存 → 对方不可见 → 刷新持久”的用例，以及注销/已读并发用例、390px 手机底部导航用例。
6. 拆分 CI：`.github/workflows/quality.yml` 验证代码质量，`.github/workflows/ci.yml` 验证 Docker 生产镜像；版本统一 Node 22 + pnpm 10。Dockerfile 健康探针读取实际 PORT，Compose 带 init、退出宽限和进程数上限。
7. 更新根目录 README 以反映随缘网真实架构、命令、隐私约束、部署方式和测试约束。

### 发布预检（新增）

- `pnpm release:check` 仅本地只读，检查源码/构建、Git 差异与忽略规则、Docker Compose、Docker Engine、受管数据库环境变量、附件持久路径和 48 小时内数据库+附件同周期备份。不会读取或打印连接串，也不连接数据库或启动容器。
- `pnpm release:check --json` 输出可审计的机器报告；`pnpm release:check:strict` 在任何生产前置条件缺失时以非零状态阻止部署。这不替代 HTTPS、真实容器运行、回退演练和上线后业务验收。
- 2026-10-08 本地检查源码就绪，但部署阻断项为 Git 工作区未提交、Docker Engine 未运行、部署环境尚未注入 `NEON_DSN` 和 `UPLOAD_DIR`。已具备新的源码归档及数据库/附件本地备份；异地恢复与正式密钥交付须在部署主机单独验收。
- Dockerfile 已补运行时 `scripts/neon-schema.sql`，使镜像自带基线及增量迁移 SQL；直接进程启动时 HOST 默认回环，Compose 明确开启容器内网监听。Docker CI 增强为构建后启动镜像校验迁移 SQL、静态资源、生产依赖和附件目录；这项 Docker 实际验收仍要在可运行 Engine 的 CI/部署主机完成。

## 四、生产发布仍需完成

以下**不能**由本次本地测试代替：

1. **受控提交**：当前 `main` 工作区含大量历史未提交或未跟踪源代码。先审查所有变更、剔除敏感信息和临时产物，明确原有正式测试文件应纳入版本管理；禁止无审查执行 `git add .`，并保留回滚点。
2. **镜像实际构建**：当前 Windows Runner Docker CLI 可用，但 Docker Engine 未启动，尚不能声明镜像构建/运行成功。须在目标 Docker 主机或完成代码推送后的 GitHub Actions 构建并记录镜像摘要。
3. **环境与持久化**：受控密钥管理配置 `NEON_DSN`；`UPLOAD_DIR` 指向挂载持久卷；确认实例只读根、非 root 和附件备份可恢复。
4. **域名 HTTPS**：目标域名和 TLS 证书；代理应覆盖而不是拼接 `X-Forwarded-For`，`TRUSTED_PROXY_IPS` 只列直接代理 IP，不配置通配符。
5. **灰度/上线验证**：新版本在正式站点可访问，检查 `/api/health`、`/api/ready`、根页及深链、实际 JS/CSS、签名图片与授权试点账户的完整业务旅程，核对运行版本/日志及错误率。
6. **备份与回退演练**：数据库 + uploads 同时备份，确认恢复方案和上一稳定镜像；优先代码回退，不因部署失败擅自覆盖 `public` 或删除附加表。
7. **真人试点数据**：当前真实推荐曝光/关系反馈为零，不得据此修改推荐权重或宣传算法有效。运营先获得授权的有效供给，再统计真人双方回应、活动签到和自愿反馈。

## 五、标准操作顺序

本地发布闸门：

```bash
pnpm install --frozen-lockfile
pnpm lint
pnpm test
pnpm build
pnpm e2e
pnpm release:check  # 解释本机与上线主机的缺口
node --check server/neon-gateway.mjs
```

目标 Docker 主机（已经通过密钥管理安全提供环境变量之后）：

```bash
docker compose -f compose.prod.yml config --quiet
docker compose -f compose.prod.yml build
docker compose -f compose.prod.yml up -d
docker compose -f compose.prod.yml ps
curl -fsS http://127.0.0.1:8080/api/ready
```

生产发布必须使用明确的部署版本、受控滚动替换/健康检查与回退流程。不要在正式同源服务上照抄旧式 `kill <网关pid>` 热加载操作，旧版守护脚本仅适用于其对应的 7000 网关部署方式。

更多详见 `docs/12-发布与回退手册.md`、`docs/17-完整前后端生产部署与验收.md`、`docs/16-关系反馈试点验收与发布清单.md`。
