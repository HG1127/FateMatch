# 07 契约设计

## 分层契约

| 层 | 对外契约 | 说明 |
| --- | --- | --- |
| UI → Service | `useStore()` 暴露的状态与动作（会话、世界快照、各域动词） | 页面只消费语义化动作，如「心动某人」「报名活动」 |
| Service → Repository | `loadWorld(): Promise<World>` / `syncWorld(diff)` / 各表读写函数 | World 为全量业务快照类型；diff 为增改删三组 |
| Repository → 数据服务 | 记录 ↔ DTO 的双向映射 | 字段 snake_case ↔ 驼峰 DTO 只在此层转换 |
| 账号服务 | 注册 / 登录 / 取会话头 | 令牌经自定义请求头透传，适配代理部署 |

## 数据契约约定

- DTO 类型 PascalCase，与表名一一对应（如 posts ↔ Post）；列表型字段在 DTO 中为数组，在记录中为 JSON 文本，转换只在仓储层。
- 时间字段：记录侧 `created`（可读串）+ `at`（排序值）；DTO 侧统一保留两者。
- 空值语义：可选字段用 `undefined`，不用空串占位。

## 错误契约

- 服务层抛 `Error`，message 为可直接展示的中文文案；UI 捕获后 toast，不再二次加工。
- 渲染期异常由全局错误边界兜底并自动上报（含组件栈前 8 帧）。
- 网络 / 权限失败在仓储层转换为中文文案，不透传存储层原始报错。

## 只读旁路契约（后台数据维护）

- 盘点：逐表取总数，单表失败记 `count = null` 不阻断其余表。
- 备份：逐表全量导出为 JSON 并触发下载；导出前剥离会话签名密钥字段；返回总条数与被跳过表名单。

## 管理端点（v1.6）

| 端点 | 权限 | 语义 |
| --- | --- | --- |
| `POST /api/admin/users/:idOrEmail/reset-password` | 仅掌柜 | 账号找回路径：生成一次性临时密码（12 位、去易混淆字符），落库为 bcrypt 哈希，明文仅本次响应返回、系统不留存；重置事件服务端日志留痕（不含明文），运营日志由掌柜侧补记 |
| `GET /api/health?deep=1` | 公开 | 深度健康检查：在进程存活之外额外探测数据库连通性（`select 1`），DB 故障时返回 500 |
| `GET /api/metrics` | 仅掌柜（v1.9） | 运行指标（内存计数、重启清零、不含业务数据）：运行时长、请求量与状态码分布、平均耗时、慢请求、限流命中、登录失败 / 锁定 / 锁定期拒绝、超大请求体、上传数与字节、注销级联数、密码重置数、违规词拦截数（v1.12）、表数、堆内存 |

配套服务端强制（同版）：停用账号登录与持令牌请求一律 403；拉黑双方之间私信 / 心动建行被拒；私有表建行仅本人（owner_sid = 我）。

### 关系与消息真实性契约（v1.13）

- `user_likes` 仅允许 `owner_sid = 当前登录账号` 的本人意愿写入；系统不得通过哈希、随机或种子逻辑制造反向「有意」。
- `chat_messages` 建行时 `from_sid` 必须等于当前登录账号，且 `sid_a / sid_b` 双方必须在 `user_likes` 中各自存在一条真实反向记录；未 mutual 时服务端返回 403。
- 消息创建同时执行双向拉黑检查；前端隐藏入口不能替代服务端权限。
- `chat_messages.sid / sid_a / sid_b / from_sid / at`、`user_likes.owner_sid / target_sid` 等关系归属字段建行后不可通过更新接口改写。
- “输入中”“已读”“回复”只能由真实业务事件产生；当前未实现的状态不得由前端定时器模拟。

## 社区内容方向（v1.13）

- 新建帖子 `topic` 仅允许：`认识我 / 兴趣见闻 / 活动回顾 / 想一起做`；服务端强制校验，直接调用集合 API 也不能绕过。
- 已存在的旧兴趣话题帖子继续可读、可搜索、可精选，更新其他字段时可保留原 topic；但任何帖子都不能被主动改写成旧的泛兴趣话题。
- 活动详情中的「写篇活动回顾」会把草稿方向一并带到 `活动回顾`；发帖表单按方向展示写作提示，目标是帮助其他会员了解“这个人”或“这场活动/同行计划”，而不是做泛生活内容流。
- 2026-09-28 对真实 `public` 只读盘点：现存 11 篇帖子全部属于旧兴趣话题（汉服 3、国风美学 2、山与海 2、慢生活 2、诗与远方 1、食记 1）。本轮不迁移、不删除，避免篡改会员历史内容。

## 内容安全与审计端点（v1.12）

| 端点 | 权限 | 语义 |
| --- | --- | --- |
| `GET /api/admin/security-events?limit=&type=` | 仅掌柜 | 最近安全事件倒序（≤200 条）：登录成败 / 锁定 / 限流命中 / 违规词拦截 / 停用恢复 / 角色变更 / 密码重置与修改 / 注销与删帖级联。身份已脱敏（`ad***@x.com`），落库保留 90 天自动清理 |
| `GET /api/admin/word-filter` | 仅掌柜 | 返回 `{defaults, words}`：内置底线词（只读）+ 掌柜自定义追加词 |
| `PUT /api/admin/word-filter` | 仅掌柜 | body `{words: string[]}`（去重、单个 ≤30 字、≤200 个）全量覆盖自定义词表，保存即时生效；自定义词存密钥表 `gateway_meta`，不经公开读接口外露 |

配套服务端强制（同版）：公开内容写路径（动态正文 / 话题、评论、活动标题 / 描述 / 要求、昵称 / 简介）命中违规词返回字段级 400「内容包含违规词」；私信 / 名片 / 举报等私密场景不拦；掌柜豁免（处置违规内容不被自己拦下）。`security_events` 表无权限规则、不经通用集合接口暴露（任何身份访问均 404），只写不读改删。

## 真实试点观测端点（v1.13）

| 端点 | 权限 | 语义 |
| --- | --- | --- |
| `GET /api/admin/pilot-metrics?days=7` | 仅掌柜 | 返回真实试点聚合：有效供给/城市分布、实际推荐下发、候选覆盖率、头部 10% 曝光占比、单人最高曝光、来源分布，以及单向有意/互相有意/开启会话/双方回应/真人消息/活动报名/真实到场；不返回 viewer/target 明细 |

配套服务端行为：`GET /api/discovery/profiles` 成功返回候选后，由服务端把“实际下发”写入内部表 `discovery_exposures`；按 `viewer × target × source × Asia/Shanghai 日期` 唯一，刷新/重试不会重复放大。明细仅含 viewer、target、来源、日期与时间，不记录点击轨迹、停留时长、消息正文或页面行为序列；在线表按 35 天窗口清理。该表不挂通用 collection 权限，任何普通/管理员身份都不能经 `/api/collections/discovery_exposures/...` 枚举原始明细；账号注销会同步清理相关曝光。掌柜聚合指标统一排除演示账号、管理员和已停用账号。

## 关系反馈专用端点（试点扩展，2026-10-08）

| 端点 | 权限 | 语义 |
| --- | --- | --- |
| `GET /api/me/relationship-feedback/:otherSid` | 仅登录本人 | 只返回本人对指定对象的 `{available,eligible,outcome}`，不返回对方选择；新表未迁移时明确标记不可用 |
| `PUT /api/me/relationship-feedback/:otherSid` | 仅登录本人 | `{outcome:'continue'|'pause'|null}`，null 撤回；非撤回提交必须已互配且有未撤回的真实消息 |
| `GET /api/admin/pilot-metrics?days=7` | 仅掌柜 | `funnel.feedbackContinue` / `funnel.feedbackPause`：观察窗口内更新的当前选择聚合，不返回逐人详情 |

`relationship_feedback` 不挂通用集合规则，`/api/collections/relationship_feedback/records` 对任何身份 404。每名成员对每个对象唯一保存一条当前状态，可改选/撤回，无自由文本与变更历史；不通知对方，不自动更改互配/聊天/推荐。账号注销级联清理本人及关联对象反馈。

## 附件与账号端点（v1.8）

| 端点 | 权限 | 语义 |
| --- | --- | --- |
| `POST /api/uploads` | 登录成员 | body `{purpose, image}`，`purpose ∈ profile/post/event/chat/admin`；jpeg / png / webp / gif 解码后 ≤8MB。成功后落盘 `v2-<purpose>-*`，返回带 HMAC capability 的 `{url, bytes, purpose}`；上传失败不允许回退 dataURL 入库 |
| `GET /api/uploads/:name?sig=...` | capability 持有者 | 仅允许 `v2-*` 文件且签名必须正确；缺签名、错签名、legacy 文件名或路径异常统一 404，避免泄露资源存在性。响应 `private` 长缓存 + `nosniff` + `no-referrer` |
| `DELETE /api/collections/users/records/:id` | 仅本人 | v1.8 起事务级级联清理本人数据（详见 09「附件与会话生命周期」） |

令牌契约：payload 含 `pv`（密码指纹 = HMAC(会话密钥, 密码哈希) 前 12 位，不暴露哈希本体）；`pv` 与当前密码不符的请求一律 401「密码已变更，请重新登录」。v1.8 前的存量令牌无 `pv`，过渡期（≤14 天）放行。
