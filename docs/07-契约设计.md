# 07 契约设计

## 分层契约

| 层 | 对外契约 | 说明 |
| --- | --- | --- |
| UI → Service | `useStore()` 暴露的状态与动作（会话、世界快照、各域动词） | 页面只消费语义化动作，如「心动某人」「报名活动」 |
| Service → Repository | `loadWorld(): Promise<World>` / `syncWorld(diff)` / 各表读写函数 | World 为全量业务快照类型；diff 为增改删三组 |
| Repository → 数据服务 | 记录 ↔ DTO 的双向映射 | 字段 snake_case ↔ 驼峰 DTO 只在此层转换 |
| 账号服务 | 注册 / 登录 / 取会话头 | 令牌经自定义请求头透传，适配代理部署 |

## 数据契约约定

- DTO 类型 PascalCase，与表名一一对应（如 posts ↔ Post）；列表型字段在 DTO 中为数组，在记录中为 JSON 文本，转换只在仓储层。
- 时间字段：记录侧 `created`（可读串）+ `at`（排序值）；DTO 侧统一保留两者。
- 空值语义：可选字段用 `undefined`，不用空串占位。

## 错误契约

- 服务层抛 `Error`，message 为可直接展示的中文文案；UI 捕获后 toast，不再二次加工。
- 渲染期异常由全局错误边界兜底并自动上报（含组件栈前 8 帧）。
- 网络 / 权限失败在仓储层转换为中文文案，不透传存储层原始报错。

## 只读旁路契约（后台数据维护）

- 盘点：逐表取总数，单表失败记 `count = null` 不阻断其余表。
- 备份：逐表全量导出为 JSON 并触发下载；导出前剥离会话签名密钥字段；返回总条数与被跳过表名单。
