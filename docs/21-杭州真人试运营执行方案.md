# 随缘网｜杭州封闭真人试运营执行方案 V1.0

日期：2026-10-09
状态：**运营工具及程序拟定；尚未招募或邀请真实参与者，尚未收集真人同意**。本方案只能在独立 staging HTTPS + 真机安全验收通过后启动。请勿把 Git 中的样例数据当成真人用户。

## 1. 试点目标、范围与期限

- 城市：首批限定**杭州**，避免人数稀释为全国空池；技术现有供给仍需根据正式环境只读复核。
- 第一阶段（3–5 天）：6–8 名明确同意的成年邀请制参与者，验证登录、资料、匹配、私信和举报流程；绝不制造虚假互配或群发机器消息。
- 第二阶段（再 9–11 天）：在风险受控且双向可匹配的前提下扩大至 **12–20 名明确同意的成年参与者**，共约 14 天。不承诺一定匹配成功。
- 先根据参与者**自愿提供**的性别、希望认识对象及城市判断池中有双向资格的真人；人数本身不能替代供需适配。建议试点期间筹备 1–2 场选择参加的公共场所轻量活动，由明确身份的组织者管理。
- 参加完全自愿；不要求付费、转账、展示敏感身份证号、透露婚姻/财富证明；不以“匹配度”作为对人的价值评判。平台核验供应商尚未接入，运营需如实解释年龄为本人确认状态。

## 2. 启动前必要条件（Go/No-Go）

1. 实际 staging 域名 + HTTPS、访问控制、独立数据库、独立上传卷已验收；备份与回退责任人明确
2. 实体 iOS 与 Android 各至少一台完成登录、发现、聊天、举报、注销及弱网人工测试
3. 明确试点负责人、数据保护负责人和举报应急联系人（在受限运营系统内部登记，**不要提交 Git**）
4. 所有参与者明确确认已满 18 岁、阅读隐私说明、理解核验未开通、同意在封闭试点接触其他自愿用户，能随时停止或退出
5. 运营工单准备：骚扰/诈骗/线下安全紧急升级渠道，暂停邀请及下线/封禁权限演练成功
6. 试点追踪仅收聚合数据与最少必要运营记录，禁止导出个人聊天全文、匹配对象名单或联系资料到工作日志/公开表格

如任何 P0（疑似未成年人进入、越权访问、用户隐私泄露、未经同意线下骚扰、财产诈骗高风险）发生，立即停止新增招募，启动安全处置并保护证据；不要在项目公开 issue 中附个人信息。

## 3. 邀请制试点执行流程

**D-3 ～ D0 准备**：确认两种真机验证结果 → 核验 staging 备份与权限 → 创建受限匿名编号表 → 每位候选单独发送参与邀请 → 明确告知数据使用与退出机制 → 在受限存储中记录同意的时间、版本、渠道，不将同意记录推送 Git。

**D1 ～ D3 可信入组**：参与者自行注册并确认必要资料，查看“核验未开通”解释，自愿设置展示范围。管理员看错误率/有效资料，不读取私聊。建立真实匹配供给后才计算曝光。

**D4 ～ D7 双向互动**：只记录实际系统下发/用户选择/双方互有意/首条回复等聚合事件，允许随时撤回“有意”。运营不得冒充对象打招呼，也不得因没有回复向对方施压。

**D8 ～ D14 活动与反馈**：自愿活动报名 → 公开地点费用和取消规则 → 现场组织者安全签到 → 双方各自自愿填写“愿意继续认识/先暂停认识”。对方不可看本人关系反馈，不能以此自动推断配对成功率。每日处理工单并观察退出情况。

**结束复盘**：输出匿名化漏斗、不同城市/范围覆盖、错误/安全问题和代表性改进建议；人数很少时只做定性诊断，暂不自行调推荐权重、加 AI 婚恋建议或公布“成功率”。

## 4. 最小化指标（管理员已有功能）

管理员界面：**系统设置 → 数据总览 → 试点漏斗与曝光公平**，以及 `GET /api/admin/pilot-metrics?days=7` 或 `?days=14` 的管理员授权聚合接口。记录汇总时至少区分：注册/有效资料人数、服务端真实候选曝光、单向有意、双向 mutual、打开会话、双方真实回复、活动报名、实际签到、个人自愿反馈、举报与申诉。

- 所有统计排除演示、管理员和封禁账号，不把账号创建/推荐数当作有效交流
- 不把未回复、撤回、关系反馈当成对他人“心理/人格”的诊断；不向第三方披露私有偏好
- 小样本（例如低于 5 人的分组）即便是汇总数据也可能被反推出个人身份。对外报告合并分组或隐藏小单元格，只让经过授权的管理员查看真实总数；严禁传播逐人关系图谱。
- 归因时保留小样本不确定性，不捏造曝光、双向联系或成功故事

## 5. 内部运营阈值（管理目标，不是向用户的服务承诺）

| 判定 | 内部处理门槛 |
| --- | --- |
| P0 安全或隐私事故 | 立即暂停招募，人工核实并执行应急流程 |
| 注册/核心链路无法使用 | 暂停扩批，恢复到经验证版本 |
| 非授权访问 | 任何一例均进入高优先级复核 |
| 关键路径通过 | 在邀请下一批前，至少由真人自愿完整走通注册、资料、双向愿意、发信和可选退出 |
| 反馈及统计可信 | 只呈现已发生的真实行为及去身份化聚合，不补“好看”的数字 |
| 试点结束 | 负责人签署 Go / Fix / Stop 决定，并列出遗留问题 |

## 6. 可直接复制使用的邀请文案（仅运营人工发送给明确愿意接收邀请者）

不要群发未经同意的真实个人通讯录；不要误导为正式全面上线。试点启动前将 staging 的实际访问控制/用户可理解的隐私说明/有效联系方式补全，文案里不写尚未核实的功能承诺。

## 7. 每日复盘格式（**仅模板**）

日期（本地时区）、部署 SHA、环境、累计已同意人数/已注销人数、必要资料人数、真实曝光数、单向有意/互相有意/双方回应数、报名/现场到场数、举报和 P0/P1 数量、遇到的可复现阻碍、当日修复责任人、次日开放/暂停决定。

实际日报与入组/退出同意记录仅存受限运营系统，不落入本公共代码仓库；不得包含邮箱、电话、私聊内容、姓名、精确线下行踪或匹配双方身份。需要截图时先脱敏。

## 8. 本阶段未自动执行的现实事项

没有参与者名单、可发送的授权邀请渠道，也没有可访问的预发布 HTTPS 站点，所以**本阶段不得称为招募完成、真实手机测试通过、真人试运营已启动**。只在指定运营负责人取得用户自愿同意和具体预发布资源后开展。
