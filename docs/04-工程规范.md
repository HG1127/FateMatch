# 04 工程规范

## 目录结构（Feature First）

```
src/
  pages/            路由页面：只做组合与交互编排，不写业务逻辑
  components/
    ui/             共享基础组件（Radix 封装）
    ui.tsx          原子样式组件（按钮 / 卡片 / 徽章等）
    <feature>/      业务组件按功能域分组：community / events / explore /
                    home / matches / me / safety / verify / yuanfen / local
  lib/
    store.tsx       服务层主入口：会话、世界快照、各域动作
    repo.ts         仓储层：实体 ↔ 记录映射、差量同步、删除护栏
    pb.ts           数据服务客户端与代理适配
    localAuth.ts    账号服务：注册 / 登录 / 会话头
    <domain>.ts     领域纯函数：badges / festivals / region / art …
    dataExport.ts   后台数据盘点与备份导出
```

## 分层与依赖方向

**UI（pages / components）→ Service（lib/store 与领域 lib）→ Repository（lib/repo）→ 数据服务客户端（lib/pb）**

- 严禁组件直接调用数据服务客户端；确需直连的只读场景（后台盘点）必须包在 lib 的服务模块里。
- 页面之间不互相 import；共享状态一律经服务层。

## 命名规范

| 对象 | 规范 | 例 |
| --- | --- | --- |
| 组件文件 / 组件 | PascalCase | `ProfileCard.tsx` / `ProfileCard` |
| Hook | use 前缀小驼峰 | `useStore` |
| 服务函数 | 小驼峰动宾 | `loadWorld`、`syncWorld`、`exportBackup` |
| 类型 | PascalCase，数据传输对象以语义命名 | `DataStat`、`FeatureKey` |
| 数据表 / 字段 | snake_case | `post_comments`、`author_sid` |
| 业务主键 | `sid`（与存储层自增 id 分离） | — |

## 测试规范

- 单元测试覆盖 lib 下纯函数与仓储层差量逻辑（vitest，`pnpm test`）。
- 提交前三道闸：`pnpm lint`、`pnpm build`、`pnpm test` 全绿。
- 渲染期不得调用不纯函数（如取当前时间），须在模块级或 effect 内取值。

## 检查规则政策

- `react-refresh/only-export-components` 降为 warning：只影响开发期热更新体验，不影响正确性与生产产物；桶文件（组件 + 常量同文件）允许存在。
- 构建配置文件（Node 侧）允许 `any`：插件接口本身无类型。
- 其余规则保持 error，不许用 disable 注释绕；确需豁免须在代码审查中说明并登记。

## 禁止事项

- 禁止在生产代码保留 Mock 分支（原型阶段已结束，全仓 grep 无残留）。
- 禁止页面内写业务逻辑或直接拼 SQL / 记录字段。
- 禁止业务逻辑与 Schema 各写一份：字段映射只在仓储层。
- 禁止绕过删除护栏直接批量删记录（护栏见 06 不变量）。
