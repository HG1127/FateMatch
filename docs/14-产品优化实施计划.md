# 14 产品优化实施计划

## 1. 基线与目标

- 优化前 Git 基线：`25c1589`（2026-09-26，已推送 `origin/main`）。
- 产品目标：在不推倒 React + Neon/Postgres 现有架构的前提下，把随缘网从“功能完整的婚恋原型”推进到“可由真人小规模试运营、状态可信、隐私可控、核心闭环可验证”的版本。
- 本计划以真实用户行为为第一约束：系统不得冒充会员产生喜欢、回复、已读、核验等行为。
- AI、付费、复杂推荐、全国扩张暂不作为当前主线；先建立真实数据与可验证闭环。

## 2. 五个 Release Blocker

### RB1 真人行为真实性

必须完成：
- 移除模拟真人回复、模拟输入中、模拟已读。
- 移除哈希规则制造的“对方也喜欢你”。
- 演示人物、帖子、活动与真实登录会员隔离；演示人物不可进入真人互动。
- 成功故事、宣传统计没有真实来源时必须删除或明确标记为示例。

验收：
- 任意真人账号的“喜欢 / 回复 / 已读 / 核验”状态都能追溯到真实用户或管理员动作。
- 自动化测试验证单边喜欢不会产生 mutual。

### RB2 真实资料与成年边界

必须完成：
- 新账号不自动填充性别、寻找对象、生日、城市、身高、职业等个人事实。
- 未确认必要资料的用户不进入推荐池。
- 推荐前至少确认性别、寻找对象、出生日期、城市，并满足成年人规则。
- 数据库缺失字段按“未知”处理，不再回填虚构默认值。

验收：
- 新注册会员的未知资料保持未知。
- 未完成必要资料或未满 18 周岁的账号无法获得或进入真人推荐。

### RB3 关键写入可信

必须完成：
- 资料保存、喜欢、发消息、报名、取消报名、举报分别拥有明确成功/失败结果。
- UI 不再以本地状态更新替代服务端保存成功。
- 关键命令支持失败恢复和幂等，失败保留用户输入。

验收：
- 断网/服务端 4xx/5xx 时不能提示“已成功”。
- 重试不会重复报名、重复喜欢、重复发消息。

### RB4 隐私与访问边界

必须完成：
- 建立访客、会员、互配对象、活动主办方、管理员的数据可见矩阵。
- 游客不默认消费真实会员完整资料作为营销内容。
- 联系方式、活动报名、照片、核验状态按最少披露原则展示。
- 提供可到达的隐私、安全、注销与帮助入口。

验收：
- 每类敏感数据存在服务端权限测试。
- 页面文案与实际存储/共享方式一致。

### RB5 核心业务契约恢复

目标链路：

`注册 → 本人确认资料 → 真人推荐 → 真实表达有意 → 双向 mutual → 真人消息 → 安全线下活动`

必须完成：
- 非 mutual 用户不能直接开启完整聊天。
- 推荐先过资格/安全硬条件，再做相关性排序。
- 自动开场白只能作为草稿，必须由本人确认后发送。
- 活动取消、签到、举报有完整状态变化。

验收：
- E2E 覆盖上述主链路和拒绝路径。
- 任何一步失败都可解释、可重试或可退出。

## 3. 分阶段执行

### 阶段 A：可信基础（当前执行）

1. 清除模拟真人回复、输入中、已读。
2. 清除伪造 mutual 逻辑。
3. 登录态隔离演示内容；真人推荐排除演示账号。
4. 新会员资料改为未知初始态，并补齐必要资料编辑。
5. 关闭模拟手机/实名/头像核验，改为诚实的未开通说明。
6. 删除无依据首页运营数字和“100%验证”等承诺。
7. 修复 ESLint 扫描边界，建立可靠基线。

退出门槛：
- 测试、构建通过。
- 核心源码 lint 无 error。
- 新增真实性回归测试。

### 阶段 B：跑通核心关系闭环

1. 推荐资格改为双向条件。
2. mutual 后才能进入会话。
3. 开场白改为“生成草稿 → 本人编辑 → 确认发送”。
4. 匹配百分比弱化为“规则参考 + 推荐理由”。
5. 登录首页任务化：待回复、今日推荐、已报名活动、资料待完善。
6. 导航收敛为：推荐 / 活动 / 消息 / 我的。

### 阶段 C：可靠性与安全线下

1. 将 `syncWorld` 中的关键写操作拆成明确命令 API。
2. 报名取消同步撤销提醒/联系方式访问。
3. 签到改为活动时段 + 主办方核销/签到码。
4. 举报增加受理编号、状态、处理结果与申诉。
5. 页面级查询、后端过滤分页、局部错误与重试。
6. `server/neon-gateway.mjs` 按 auth / profile / matching / messaging / events / safety / admin 分模块。

### 阶段 D：真实试点后增强

1. 城市级小规模真实供给试点。
2. 基于真实反馈调整推荐权重与曝光公平。
3. 社区只保留能帮助“了解人/了解活动”的内容。
4. 再评估 AI 推荐、AI 关系助手、人工牵线与商业化。

## 4. 产品指标

北极星指标：
- **每周建立有效双向交流的真实用户占比**。

核心漏斗：
1. 注册成功。
2. 必要资料确认。
3. 进入推荐池。
4. 推荐曝光。
5. 查看详情。
6. 表达有意。
7. 双向 mutual。
8. 首条真人消息。
9. 首次真人回复。
10. 有效双向交流。
11. 活动报名。
12. 真实到场。
13. 自愿反馈继续认识/暂停寻找。

所有指标必须排除：
- 演示账号。
- 自动生成回复。
- 管理员测试账号。
- 无真实来源的种子行为。

## 5. 工程规则

- 保留 React + TypeScript + Vite + Neon/Postgres 技术栈。
- 不因 UI/产品问题更换数据库。
- 变更优先增加测试，再改行为。
- P0 改动必须可回退到 `25c1589`。
- 每一批优化单独提交，避免把产品重构、视觉重构和基础设施重构混在一个提交。
- VibeX 平台集成、app id、PocketBase 路由与本地回传约束保持不变。

## 6. 当前第一批执行范围

本批只做“真实性”相关变更：
- 真人消息不再自动生成对方回复/输入/已读。
- mutual 仅由双方真实 like 记录产生。
- 演示数据与登录会员数据隔离，演示对象不可进入真人推荐。
- 新账号不再生成虚假性别/生日/城市/职业。
- 匹配必要资料增加真实填写入口。
- 模拟核验停止授予验证徽章。
- 首页静态运营数字和绝对化验证/隐私承诺移除。
- 默认成功故事明确为示例。
