# 12 发布与回退手册（含 v1.0 发布记录）

## 发布流程（每次发布三步）

1. **冒烟**：`NEON_DSN='postgresql://…' pnpm e2e` —— 3 例全过才继续（隔离环境自动建销，不碰生产）。
2. **三道闸**：`pnpm lint`（0 error）、`pnpm test`（全绿）、`pnpm build`（成功）。
3. **健康抽查**：数据网关健康检查、页面服务 200、抽一条业务数据核对（如动态条数）。

三步全绿即视为可发布；本环境为容器内常驻服务，代码合入本地主干并重启网关即完成上线。

## 回退与恢复

- **回退到旧数据服务**：停数据网关 → 进程管理器启动旧数据服务进程。代价：丢失切换后新写入的数据，仅作故障兜底（见 11）。
- **容器重启后恢复**：连接串不落盘（安全约定），重启后需重新拉起网关：运行启动脚本按提示粘贴连接串，或以环境变量方式启动。切换当日实测恢复耗时约 1 分钟。
- **数据库层回退**：Neon 控制台 PITR / 分支（建议开启，见 11）。
- **备份演练**：`NEON_DSN='postgresql://…' node scripts/neon-backup-drill.mjs` —— 生产只读导出全量 → 装入一次性隔离空间 → 逐表核对行数与内容指纹 → 销毁。2026-09-22 首跑通过（22 表 / 58 行全一致）。
  注意：Neon 连接池为事务模式，会话级 `set search_path` 会跨连接泄漏；本仓所有脚本一律事务级设置 + 全限定表名。
