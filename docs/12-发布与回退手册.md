# 12 发布与回退手册（含发布记录）

## 发布流程（每次发布三步）

1. **冒烟**：`NEON_DSN='postgresql://…' pnpm e2e` —— 11 例全过才继续（隔离环境自动建销，不碰生产）。
2. **三道闸**：`pnpm lint`（0 error）、`pnpm test`（全绿）、`pnpm build`（成功）。
3. **健康抽查**：数据网关健康检查、页面服务 200、抽一条业务数据核对（如动态条数）。

三步全绿即视为可发布；本环境为容器内常驻服务，代码合入本地主干即完成上线准备。网关由看门狗看护（v1.5 起）：上线新网关代码 = `kill <网关pid>`，看门狗数秒内自动以新代码拉起；界面代码由页面服务热加载，无需动作。

## 回退与恢复

- **网关进程崩溃 / 假死**：看门狗自动拉起（指数退避 1s→60s，稳定运行 10 分钟后重置；健康检查连续 4 次失败判假死，杀掉重拉）。日志：`logs/watchdog.log`。
- **回退到旧数据服务**：停看门狗（`kill -TERM <看门狗pid>`，会连同网关一起干净退出）→ 进程管理器启动旧数据服务进程。代价：丢失切换后新写入的数据，仅作故障兜底（见 11）。
- **容器重启后恢复**：连接串不落盘（安全约定），看门狗与网关的内存态一起丢失。恢复：`NEON_DSN='postgresql://…' bash scripts/start-neon-gateway.sh`（或运行脚本按提示粘贴连接串）——看门狗冷启动并拉起网关，脚本内置 90 秒就绪等待。切换当日实测恢复耗时约 1 分钟。
- **看门狗接管已有网关**：直接运行 `bash scripts/start-neon-gateway.sh`（无需连接串）——从在跑网关的进程内存接管连接串，停旧拉新，约 20 秒。
- **全新环境种子化**：新库建表（`scripts/neon-schema.sql`）后运行 `NEON_DSN='postgresql://…' node scripts/seed-demo-data.mjs`，幂等灌入演示内容夹具（`scripts/demo-seed.json`，只含种子用户署名行，导出时经隐私核对，不含凭据）。灌入后演示内容全员共享、可互动。夹具可用 `--export` 从任何已含演示内容的库重新导出。
- **数据库层回退**：Neon 控制台 PITR / 分支（建议开启，见 11）。
- **附件备份**：`uploads/` 目录是会员上传图片的唯一存储（不入 git、不在数据库），备份数据库的同时须一并归档该目录（如 tar 打包异地存放）；备份演练脚本只覆盖数据库。
- **备份演练**：`NEON_DSN='postgresql://…' node scripts/neon-backup-drill.mjs` —— 生产只读导出全量 → 装入一次性隔离空间 → 逐表核对行数与内容指纹 → 销毁。2026-09-22 首跑通过（22 表 / 58 行全一致）。
  注意：Neon 连接池为事务模式，会话级 `set search_path` 会跨连接泄漏；本仓所有脚本一律事务级设置 + 全限定表名。

- 注册限流上调 20 → 50 次/时（预览代理形态下全站可能共享出口 IP，留足真实注册余量；防爆破锁定不受影响）

**验证**：发布冒烟 11/11（新增断言组：改密后旧令牌 401 / 新登录 200、匿名上传 403、登录上传 + 读取 + 类型校验 400、路径穿越 404、注销级联逐项核对（目录 / 动态 / 活动 / 名单 / 收藏全清）、会话保留、注销后旧令牌匿名化 403）；三道闸全绿；线上抽查见发布时记录。

**回退**：网关 + 前端代码变更，无 schema 迁移。回退后带指纹令牌在旧网关下仍可验签（多余字段被忽略）；注意 `uploads/` 目录需保留——完整回退会让 v1.8 期间上传的图片 URL 失去读取路由（旧代码无该端点）。

## v1.6 发布记录（2026-09-23）

**内容**：后端能力补齐——封禁 / 拉黑服务端强制、账号找回路径、私密表读写收紧。

- 登录页透出 403 / 429 的服务端提示（停用原因、锁定倒计时），其余错误保持产品语兜底
